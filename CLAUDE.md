Agent-first 2D art application in Rust: a `klad` CLI for agents and a native editor for people with a pen, sharing one document bundle on disk. What and why: `docs/DESIGN.md`. How to build, test and send a change: `CONTRIBUTING.md`. How an agent draws with it: `docs/skill/SKILL.md`.

## Toolchain

- Rust stable through rustup with clippy and rustfmt (`rust-toolchain.toml`), `just` for recipes. `just` builds into a folder per platform, `target/` on macOS and `target/linux` (or `target/windows`) elsewhere, whatever `CARGO_TARGET_DIR` says, so a checkout shared between a Mac and a Linux machine never mixes their binaries (`KLAD_TARGET_DIR` overrides it); `just build` ends by running the binary, so a binary for the wrong platform fails there. Run cargo from the repository root, with `CARGO_TARGET_DIR` set to the same folder when calling cargo directly.
- The editor (`crates/app`, `klad open`) runs on macOS for now. It compiles and its tests run on Linux too; `klad open` exists only in the macOS build.
- The editor's panels run headless in tests through `egui_kittest` (`Editor::open` needs no GPU): click, type, drag, read sizes and accessible names. `just ui-pictures` and `cargo test -p klad-app -- --ignored start_pictures` render the UI into `scratch/ui/` with a blank canvas; `editor_picture` draws the canvas too, and `guide_pictures` renders the editor pictures in `docs/guide/` from the built samples (copy them from `scratch/ui/guide/` to `docs/images/guide-*.png`) (the kittest renderer gets the canvas resources, and the canvas is redrawn once it has caught up, since uploads made in a pass kittest did not render are lost). `just ui-time` measures UI work per frame; `just memory` (or `just memory "4096 8192"`) makes stress drawings of 4096, 8192 and 16384 px in `/tmp/klad-memory` once and prints the peak memory and time of rendering each, the numbers for the memory table in `docs/DESIGN.md`; `just drag-time` (or `just drag-time <bundle>`, which drags in a copy) measures drags on a generated poster-like drawing: how often the preview updates, the release frame and what follows it, and a layer switch.
- Journeys (`crates/app/src/editor/journeys.rs`, on the `Journey` helper in `testkit.rs`) walk a whole job through the start window and the editor the way a person would: labels, keys, drags, scrolls and pinches, never a command called directly. Each step checks what a person expects without stopping at the first miss, and a journey ends by comparing its misses with the list it carries: a new miss fails it, and so does a listed one that no longer happens (take it off the list). A journey presses only what is in sight, with the pointer: a control that is scrolled away or lies under another panel is reported as out of sight, and the journey has to do what a person would; with a menu or a window open, a click goes to the control on top. Where a journey plays the agent it runs the `klad` binary beside the open editor. `just journeys` runs them without a GPU; `just journeys <absolute folder>` also writes a picture and a `steps.md` log per journey there, and with `KLAD_GODOT=<the godot binary>` the export journey loads its files in Godot. `just inventory [folder]` writes two files there (`scratch/` by default): `inventory.md`, every command with its menu, key and description, and `controls.md`, every control of the editor by tool, panel and window with its label, value and hover hint, read from the editor opened without a window (`crates/app/src/editor/inventory.rs`).
- The sweep (`crates/app/src/editor/sweep.rs`) asks one thing of everything: does it change something a person can see, or say why not. The grid presses every tool on every kind of active layer (a click, a drag and a loop, on the layer's own mark, on another layer's paint and on empty canvas) and runs in `just test`. The command sweep runs every command in 23 prepared states, the way a menu runs it and from its keys; it takes minutes, so only `just sweep` runs it (after building the `klad` binary its jobs call). Both carry the list of acts and commands known to stay quiet, each with its reason, and fail on a new one and on a listed one that now answers (take it off the list). `just sweep <absolute folder>` also writes `grid.md` and `sweep.md` there. `KLAD_SWEEP_FRESH=1` opens a fresh drawing for every act (the default uses one editor again while an act leaves no trace), `KLAD_SWEEP_STATE=<name>` runs one state of the command sweep.
- The sizes test (`crates/app/src/editor/sizes.rs`) measures the editor in windows of three sizes, each at four interface sizes: how much of a new window the canvas gets, which panels are in sight, and for every tool, panel, window and menu the controls that cannot be brought in sight (less than half of the control shows while its panel or window is wheeled to its end) or are cut off. It reads what every control with a hover hint records about itself in test builds (`theme::hint_parts`: its box, and the part its panel lets through). It asserts nothing and is not part of `just test`: `just sizes <absolute folder>` writes a `sizes-<window>-at-<scale>.tsv` and a few pictures per size there, and `KLAD_SIZES_PICTURES=all` a picture of every state.
- Random use (`crates/app/src/editor/monkey.rs`) plays acts picked by a seed on a painting and on a sprite: tool keys, other keys, clicks and drags on the canvas, a drag ended by Esc or by the window losing the pointer, any command but Quit and Install the command, another layer, another frame, typed text, and an agent that adds, draws on, renames or removes layers on disk meanwhile. After the acts it holds the editor to its rules: no panic; after three Escapes (and Return when the timeline plays) the editor and the folder hold the same drawing and marks; the canvas shows what the same drawing shows when opened again; undoing everything gives the start, and redoing it the end, with the canvas right after each; and at the end B gives the brush and a stroke on a new paint layer lands (after the messages and windows that lie on the canvas are closed). A run is kept only when it breaks its rule every time. `just test` runs a few seeds, a run that plants a change that never reached the disk (the rules must catch it), and the kept runs: the shortest acts found that break a rule, each pinned to the rule it breaks until it is fixed (then the test says to take it off). The comparison with a fresh open only holds when the copy is made the way the editor does it: the same layer in hand through `set_active`, the onion skin off through its command, the mask's tint on. `just monkey <absolute folder>` runs `KLAD_MONKEY_SEEDS` seeds (40) of `KLAD_MONKEY_ACTS` acts (40) from `KLAD_MONKEY_FROM`, cuts each kind of failure down to its shortest run and writes `monkey.md` there; `KLAD_MONKEY_SLOW=1` also makes an act that keeps the editor busy for over four seconds a failure.
- `cargo test -p klad-app` alone does not rebuild the `klad` binary that the job and thumbnail tests run; `just test` (the workspace) does.
- macOS-only code (`crates/app/src/pen.rs`, `crates/app/src/picker.rs`) can be type-checked from Linux with `rustup target add aarch64-apple-darwin` and a small scratch crate holding the module and its objc2 dependencies (`cargo check --offline --target aarch64-apple-darwin`); the full workspace cannot, `zstd-sys` needs the macOS SDK.

## Working

- Every doc in `docs/` starts with a `_Last updated: YYYY-MM-DD HH:MM_` line; update it when the doc changes.
- Guides in `docs/guide/` are short how-to pages for people in the editor. A page opens with one sentence on what it lets you do and stays under about 300 words; each section is one task titled as the goal, verb first, done the shortest way in numbered steps of one action each (where, then what, then what happens), at most five. No option catalogues, no alternatives, no explaining how klad works inside: the editor names its options and `?` lists the keys. Keys and editor labels in bold, labels exactly as the editor writes them. Getting started is the one tutorial: a single path from a new drawing to changing a stroke.
- Never commit build output or binaries, and check `git status` before `git add -A`. `samples/` holds generators only; the bundles and pictures they make stay out of git.
- Commit messages and docs name no one: say what changed and why.
- `main` is protected: never commit on it. Work on a branch off the newest `origin/main` (`feature/...`, `bugfix/...`); it reaches `main` through a pull request.

**Done means**

- Tests for new behaviour in the crate that owns it.
- `just lint` (fmt check plus clippy with `-D warnings`), `just test` and `just audit` are clean.
- A change to a tool, a command or what a kind of layer takes also runs `just sweep`.
- A change to the layout, a panel, a window or a menu also runs `just sizes` and reads its numbers against the last ones.
- A change to undo, to how the editor follows the disk, or to what the canvas keeps between frames also runs `just monkey` with a few hundred seeds.
- A change that moves a sample's hash says why.

## Standing rules

- Every feature has a CLI form and an editor form (DESIGN principle 7): a change that adds one adds the other, with tests on both sides, unless it only makes sense on one side (the editor's view and settings; the CLI's batch, hash and test tools; the ops that draw from shapes, `ink`, `light`, `hatch`, `paint`, `scatter` and `fill --shape`, which stay CLI only).
- The editor changes a drawing only through the scene (`Scene::apply_with`, `step`, `commit_stroke`, `commit_fill`), which ends what is only shown (a layer preview), refuses to write over a change in the folder it has not read, and never writes when the folder is no longer the drawing's. A new way of changing the drawing from the editor goes through `Editor::write` (or `apply`, `set`, `timeline_apply`), which reads the folder first when it has changed; never write `doc.json` or a stroke file from the editor another way, and never keep a changed copy of the document that a save could pick up.
- No comments in code except `// TODO:`.
- Iterator chains over `for` loops where they read better; plain loops in hot pixel paths where they are clearer or faster.
- Determinism in `core`, `brush` and `render`: transcendental math through `libm`, one seeded RNG (`klad_core::rng`), no wall clock, no `HashMap` iteration order in output, parallelism only over independent units (tiles, image rows).
- Bundles are never broken by a format change: bump the format version (`klad/N` in `doc.json`) and add a migration, and update `docs/format.md` in the same change. `klad/1` (2026-11-06) started clean: the `.draw` folders before it (`draw-anything/0` to `/9`) do not open.
- Permissive dependencies only: MIT, Apache-2.0, BSD-2/3, ISC, Zlib, BSL-1.0, Unicode-3.0, CC0-1.0; fonts bundled in the editor may be OFL-1.1 or the Ubuntu Font Licence (egui's), and the fonts in `fonts/` OFL-1.1 or Apache-2.0 (`fonts/update.py` fetches them unchanged; the notices list them). No GPL, LGPL or MPL unless dual licensed with one of these. `deny.toml` holds the list and `just audit` checks it; every shipped licence text is in `THIRD-PARTY-NOTICES.md` (`just notices`).
- klad is source-available, not open source, copyright Indicode: the app is under the PolyForm Internal Use License 1.0.0 with permissions for personal use (free to build from source), proposing contributions and sharing drawings, and a limit: a company with 500,000 euros or more in revenue in its last tax year needs a bought licence per person; it also covers the builds it sells, and a bought build is such a licence (`LICENSE`; `license-file` in Cargo, since it has no SPDX identifier). `docs/format.md`, `docs/cli.md`, `docs/skill/` and `crates/client` are MIT (`LICENSE-MIT`): `klad-client` depends on none of the other crates, a format change updates `docs/format.md` in the same change, and a command change runs `just reference` (a test checks `docs/cli.md`). Outside contributions come in under the CLA (`CLA.md`).
- No em-dashes in docs, messages or UI text.
- `just build` counts the version up (patch; `minor` and `major` on request) for every release build made on the maintainer's machine; agents build with `just compile`, which does not (plain `just` is `just compile`), and commit a counted-up `Cargo.toml` and `Cargo.lock` with the next change.
